# 功能范围与创新点说明

本文档用于约束第一版实现范围，避免前端、后端、数据库各自发散。当前项目定位为“校园 + 城市混合的个性化旅游系统”，创新点侧重“社区内容生态驱动个性化推荐”。

## 第一版必须实现

这些功能需要前端、后端、数据库形成闭环，优先保证演示可跑通。

### 用户与资料

- 用户注册、登录、退出。
- 登录后返回 token，前端通过 `Authorization: Bearer <token>` 调用受保护接口。
- 用户可查看和编辑个人资料。
- 用户可查看自己的游记列表。

### 设施 / 景点查询

- 支持校园设施和城市景点统一建模为 POI。
- 支持关键词、类型、区域查询。
- 支持分页返回。
- 支持景点详情页展示评分、热度、坐标、介绍。

### 个性化推荐

- 支持热度优先、距离优先、兴趣匹配三类推荐入口。
- 支持按景点类型和距离范围筛选。
- 热门 Top10 可供首页、写日记页、圈子日志关联景点使用。
- 推荐结果至少返回名称、图片、简介、分类、评分、距离、访问量。

### 美食模块

- 支持美食列表、详情、菜系筛选、价格筛选、排序。
- 美食可关联到某个 POI，例如食堂、商圈、景区。
- 支持提交简单美食评价。

### 路线规划

- POI 数据可作为路线节点。
- 路线边数据支持最短路径计算。
- 支持两点最短路径和多点路线规划。
- 第一版地图绘制可以是前端占位，但后端需要返回时间、距离、途经点。

### 游记 / 日志

- 用户可发布个人游记。
- 游记可关联景点。
- 游记支持评分、浏览量、点赞数、评论数等统计字段。
- 景点详情页、美食详情页、个人主页可展示相关游记。

### 圈子社区

- 用户可创建、加入、退出圈子。
- 圈子有成员列表和日志列表。
- 用户可在圈子发布日志。
- 圈子日志支持点赞、评论、回复。

## 可以实现

这些功能能提升完整度，但不应该阻塞第一版核心闭环。

- 头像上传真实落盘。
- 圈子封面上传真实落盘。
- 游记图片上传真实落盘。
- 推荐理由展示，例如“因为你点赞了摄影类游记”。
- 精华日记筛选。
- 食物和景点的独立评论列表。
- 浏览记录采集。
- 收藏景点或美食。
- 其他用户资料详情接口。
- 按真实经纬度计算距离。

## 后续扩展

这些功能适合放在报告的“后续展望”，第一版不建议投入太多时间。

- AI 对话式旅行助手。
- 真实地图 SDK 路线绘制和导航。
- 实时拥挤度或实时排队时间。
- 天气、酒店、车票、门票等外部服务。
- 圈子管理员权限体系。
- 内容审核和举报。
- 多人共同规划路线。
- 支付或订单系统。

## 创新点：社区内容生态驱动个性化推荐

本项目不把推荐理解为简单的“按热度排序”，而是把社区内容和用户行为作为推荐依据。

### 数据来源

- 用户主动偏好：用户选择或填写的兴趣标签。
- 浏览行为：用户浏览过哪些景点、美食、游记。
- 收藏行为：用户收藏过哪些景点或美食。
- 评分行为：用户对景点、美食或游记的评分。
- 点赞行为：用户点赞过哪些游记和圈子日志。
- 评论行为：用户参与过哪些主题讨论。
- 圈子关系：用户加入了哪些兴趣圈子。
- 内容标签：游记、景点、美食、圈子日志上的标签和分类。

### 推荐思路

推荐分数可以由以下部分组成：

```text
推荐分数 =
  标签匹配分 * 0.30
  + 社区热度分 * 0.25
  + 用户行为分 * 0.25
  + 评分质量分 * 0.10
  + 距离便利分 * 0.10
```

各部分含义：

- 标签匹配分：用户偏好标签与 POI / 美食 / 游记标签的匹配程度。
- 社区热度分：游记数量、圈子讨论量、点赞量、评论量、浏览量。
- 用户行为分：用户历史浏览、收藏、评分、点赞带来的兴趣权重。
- 评分质量分：景点或美食的平均评分。
- 距离便利分：距离越近越适合推荐，尤其适合校园场景。

### 数据库设计含义

为了支撑上述创新点，数据库不能只设计 `景点表` 和 `用户表`，还需要保留社区与行为数据：

- 游记表记录用户原创内容。
- 圈子表和圈子成员表记录兴趣社区。
- 点赞、评论、收藏、浏览记录记录用户行为。
- 标签表和关联表统一表达内容特征。
- 评分表记录用户对景点、美食、内容的反馈。

这样答辩时可以说明：系统的个性化不是页面包装，而是由数据库中的用户行为和社区内容持续沉淀出来的。

## 数据库边界建议

后续数据库设计应从前端字段反推，但要区分四类字段：

- 必须落库：用户、POI、美食、游记、圈子、评论、点赞、评分、路线节点和边。
- SQL 聚合计算：点赞数、评论数、日志数、成员数、平均评分、热度。
- 后端临时计算：距离、推荐分数、推荐理由、路线总时长。
- 前端展示占位：真实地图、图片上传预览、分享链接、忘记密码。

第一版不要为了占位功能过度扩表。数据库应优先支撑核心闭环和创新点。
